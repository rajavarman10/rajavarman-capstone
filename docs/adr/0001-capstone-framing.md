# ADR-0001: Capstone Framing — FastAPI Docs Knowledge Assistant

- **Status:** Draft v1
- **Date:** 2026-09-02
- **Author:** Rajavarman

## Context

Developers working with FastAPI often need quick, accurate answers about specific
behavior — how dependencies work, how to configure security, how to test endpoints,
how to deploy — without re-reading the full documentation each time. This capstone
builds a small Q&A assistant over FastAPI's own documentation so a developer can ask
a plain-English question and get an answer grounded in the actual docs, rather than
relying on memory or a general-purpose search engine that may return outdated or
unrelated results.

## Decision — Solution Framing Canvas

| Box | Your answer |
|-----|-------------|
| **Inputs** | A plain-text question typed by the user (e.g. "How do I add OAuth2 security to an endpoint?") |
| **Outputs** | A text answer generated by the LLM |
| **Tools** | OpenAI's chat completion API only, for v1 (no retriever/vector database yet — added in a later week) |
| **Memory** | None — every question is answered independently; no conversation history is kept between calls |
| **Autonomy level** | Lowest — pure chatbot. It only answers when asked; it never takes an action, calls another tool, or makes a decision on its own |
| **Decision boundaries** | The system may decide how to phrase an answer; it may never take an action (e.g. modify files, call external services), and always requires a human to ask the question and read the answer |

## Consequences

- **Positive:**
  - Extremely simple to build, run, and debug — a single script with one function.
  - Fast to iterate on and cheap to run (`gpt-4o-mini`, low temperature).
  - Gives a working, testable baseline before adding retrieval complexity.
- **Negative / risks:**
  - No grounding in the actual FastAPI docs yet — the model answers purely from its own training knowledge, so it can be wrong or out of date about newer features.
  - No memory means it can't handle multi-turn/follow-up questions.
  - No source citations, so a user can't verify where an answer came from.
- **Things we'll re-visit:**
  - Add retrieval over the actual FastAPI corpus (chunking + embeddings + vector search) so answers are grounded and citable.
  - Consider adding short-term memory once multi-turn conversations become a requirement.
